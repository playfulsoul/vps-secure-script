01 先分清两种角色

Hub：监控中心提供网页，集中显示各台 VPS 的状态、图表和告警设置。
Agent：被监测端安装在每台需要观察的 VPS 上，向监控中心提供数据。

本平台集成 Beszel Agent 管理，并提供已有 Hub 的备份恢复工具。不会自动安装 Hub、购买域名、配置反向代理或申请 HTTPS 证书。

  1. 先按 Beszel 官方安装指南准备 Hub，建立管理员账户。
  2. 确认能从浏览器访问自己的 HTTPS 监控域名，使用默认 443 端口和域名根路径。
  3. 在待接入 VPS 上安装 2.1.0-beta.2，并用 vps --version确认。
  4. 保留可用 SSH 会话；接入不会代替原有 SSH 登录或防火墙管理。

密钥、令牌、备份及云盘配置属于敏感资料。不要发到评论区、公开仓库或截图中。只使用自己的 Hub 地址。

02 接入一台 VPS

首页 5 →「中央 VPS 状态监控（Beszel）」→「交互接入」
  1. 在 Hub 中选择添加系统，为这一台 VPS 建立对应记录。
  2. 从 Hub 为该节点生成的连接信息中取得公钥和令牌；不要将别的节点令牌混用。
  3. 在这台 VPS 的终端执行下方交互命令，按提示输入 Hub HTTPS 地址、公钥和令牌。敏感输入不会回显。
  4. 回到 Hub，完成添加系统并等待其显示在线；再打开 CPU、内存、网络图表。
  5. 逐台重复，避免一次批量接入后无法判断故障位置。
sudo vps monitor join-prompt
vps monitor status
vps monitor verify

root 用户可以省略 sudo。菜单中还保留基于文件的安装入口，适合已经准备好受保护凭据文件的用户；初次使用优先选择交互接入。

完成标准：本机验证通过，Hub 中对应节点在线并持续出现新数据。仅显示“Agent 正在运行”不等于 Hub 已成功接收数据。

03 状态、图表与告警怎样判断

先确认节点名称和时间正确，再观察 CPU、内存与网络速率。上下行速率是网卡在采样区间内的统计，不等于服务商承诺带宽，也不是主动测速结果。

延迟、丢包或业务可达性应使用对应网络检测；不能仅凭 CPU 正常判定网站、代理节点或整条链路正常。

配置告警

  1. 在 Hub 中配置通知渠道和接收地址。
  2. 发送测试通知，并在接收端确认实际收到。
  3. 为所需节点设置阈值和持续时间，再按实际使用情况调整。

“通知设置已保存”“测试请求已发送”都不等于邮件已送达。检查收件箱和垃圾箱；不要以关闭 SSH 或制造防火墙故障的方式测试告警。

反向代理部署的 Hub 应使用实际 HTTPS 域名作为 APP_URL，否则通知中的链接可能指向本机地址。本平台不会替你修改反向代理或邮件服务。

04 备份与恢复监控中心

以下命令在 Hub 所在 VPS 执行，不是在任意 Agent 上执行。默认适配 systemd 服务 beszel.service，数据目录 /var/lib/beszel/beszel_data。Docker 或自定义路径不能直接套用默认值。

vps monitor hub status
vps monitor hub verify
sudo vps monitor hub backup --yes

先核对状态输出识别到的是正确 Hub。备份会短暂停止服务，再恢复原来的运行状态；私下保存输出的归档路径及校验文件。归档包含账户和监测历史，应按密码资料保护。

自定义安装的进阶说明

模块支持通过 VPS_BESZEL_HUB_SERVICE、VPS_BESZEL_HUB_DATA_DIR、VPS_BESZEL_HUB_BACKUP_DIR、VPS_BESZEL_HUB_STATE_DIR、VPS_BESZEL_HUB_HEALTH_URL指定实际对象。不了解自己的部署结构时，先查安装记录，不要猜目录或服务名称。

需要恢复时

恢复会替换 Hub 数据。先另做当前备份，确认目标归档、对应校验文件及兼容性，再在维护时段执行；将示例路径替换为真实归档路径。

sudo vps monitor hub restore --archive /absolute/path/beszel-hub.tar.gz --yes

恢复工具检查归档与校验、保留原数据并验证本地健康状态。完成后还需要网页登录，检查节点、图表及通知设置；本地健康检查通过不能代替这些业务检查。

05 OneDrive 加密备份

这是进阶选项，需要先完成 rclone crypt 与 OneDrive 授权。本模块不会代办云盘授权。配置默认保存在 /etc/vps-secure/rclone/rclone.conf，应归 root 所有且不允许其他用户读取。

只使用启用加密、底层为 OneDrive 的 crypt remote。下面的 vps-onedrive-crypt 是示例名称，替换为自己的 remote；不要填裸 OneDrive remote。

sudo vps monitor hub onedrive-test --remote vps-onedrive-crypt --path roundtrip-tests --yes

先完成加密上传、下载与校验往返测试，再启用定时任务：

sudo vps monitor hub onedrive-schedule-enable --remote vps-onedrive-crypt --path scheduled --time 04:30 --timezone Asia/Shanghai --yes
vps monitor hub onedrive-schedule-status
sudo vps monitor hub onedrive-health

示例为北京时间 04:30，实际执行可能有最多约 10 分钟随机延迟。启用定时器不会立即产生一份备份；到执行后检查任务结果、云端文件和校验。一次性任务执行完成后显示 inactive，不一定是失败。

sudo vps monitor hub onedrive-retention-preview
sudo vps monitor hub onedrive-schedule-disable --yes

保留策略目前只预览，默认参考 30 天、至少 7 份，不自动删除云端文件。停用定时器不会删除既有备份。应另行安全保存加密配置和恢复所需秘密；丢失加密凭据会影响恢复。

备份 watchdog 模板需要单独部署和接入通知；启用备份定时器不等于已经启用失败邮件告警。日常仍应检查备份健康状态，并在隔离环境验证恢复。

06 月流量与额度提醒

此功能通过 vnStat 统计指定网卡收发流量，帮助观察额度消耗。网卡统计不是服务商账单：计费方向、单位、结算日期和历史覆盖范围都可能不同。

  1. 查询服务商额度、重置日、计费方式和 GB/GiB 单位。
  2. 确认主要公网网卡，不要直接照抄 eth0。
  3. 填写额度及两级提醒百分比。下面仅是“eth0、1000 GiB、每月 1 日、80%/90%”的示例。
ip -br link
sudo vps monitor traffic configure --interface eth0 --quota-gib 1000 --reset-day 1 --warn-percent 80 --critical-percent 90 --yes
vps monitor traffic status

服务商使用十进制 GB 时，将 --quota-gib 换为 --quota-gb。月周期按 VPS 本地时区计算。首次安装 vnStat 后可能尚无日记录，工具会停止配置；等待产生记录后重试，不要把没有历史数据当作当月零流量。

这里提供本机统计与状态，不代表已自动把额度告警发送到邮箱或手机。使用一段时间后，应与服务商控制台对照校准理解。

07 排错、换中心与退出

现象先检查
本机通过，Hub 离线Hub 地址、节点凭据是否匹配、HTTPS 可达性、Hub 中节点是否完成添加。
图表数据少接入时间、采样是否持续；新安装不能补回过去历史。
备份失败服务和目录是否匹配、空间、配置权限、云盘授权与 crypt remote。
没有收到邮件通知渠道、接收端、阈值与持续时间；分别核对发送和送达结果。

更换 Hub 地址可用下列命令，但新 Hub 中的节点和凭据仍要匹配；先保存当前接入资料。地址只是示例：

sudo vps monitor rebind --hub-url https://new-monitor.example.com --yes

不再监测某台 VPS 时，在那台 Agent 上执行：

sudo vps monitor leave --yes

退出前核对目标；随后在 Hub 中检查对应记录，按需要手动整理。不要把退出 Agent 当作删除整个 Hub、历史数据或云备份的操作。

反馈问题时只提供版本、脱敏错误和操作步骤，不要提供令牌、私钥、云盘配置或完整备份。
