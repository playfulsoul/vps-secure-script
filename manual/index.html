2.0.0 正式版

01 安装与开始使用

工具安装在 VPS 上，通过中文菜单操作。你电脑中的 Termius 或终端负责连接 VPS；安装命令应在 VPS 窗口中执行。

先选版本和服务器

日常使用选正式版 2.0.0。Debian 12/13、Ubuntu 22.04/24.04 有已记录的主要流程实机验证；这些记录不代表所有功能在每一种系统上的每次构建都已复测。其他系统先查兼容性说明。

安装前确认已有可用 SSH 登录，并了解服务商控制台的位置。已有网站或节点的机器，先做体检和防火墙检查，再决定是否运行初始化。

需要分阶段登录强化或集中监测时，请使用 Beta 安装说明；普通基础管理优先使用正式版。

安装正式版

  1. 通过 SSH 登录 VPS。提示符以 root@ 开头时，按下面的 root 命令执行。
  2. 如果没有下载工具，先执行准备命令。
  3. 在独立空目录中下载程序和校验文件；确认校验结果是 OK 后，安装器才会继续。
apt-get update && apt-get install -y ca-certificates curl
展开完整安装命令（在 VPS 执行）
mkdir -p ~/vps-secure-install-2.0.0 &&
cd ~/vps-secure-install-2.0.0 &&
curl -fLO https://github.com/playfulsoul/vps-secure-script/releases/download/v2.0.0/vps-secure-platform-2.0.0.tar.gz &&
curl -fLO https://github.com/playfulsoul/vps-secure-script/releases/download/v2.0.0/vps-secure-platform-2.0.0.tar.gz.sha256 &&
sha256sum -c vps-secure-platform-2.0.0.tar.gz.sha256 &&
tar --no-same-owner --no-same-permissions -xzf vps-secure-platform-2.0.0.tar.gz &&
./install.sh &&
vps

普通 sudo 用户在两条 apt-get 命令、./install.sh 和最后的 vps 前加 sudo。若目录里已有不确定的文件，换一个空安装目录。

正常结果：出现中文首页。以后 root 输入 vps，普通管理员输入 sudo vps；查看版本可输入 vps --version。

失败处理：下载、校验或安装报错时先停在该步骤。两个下载链接分别是程序包和校验文件，作用不同。

安装 2.1.0-beta.2（预发布）

此版本包含进阶登录安全和集中监测。先阅读 发布说明。下载到一个空目录；以下以 VPS 的 root 用户为例，普通 sudo 用户在安装和启动命令前加 sudo。安装程序不会自动执行安全初始化。

展开 Beta 安装命令
mkdir -p ~/vps-secure-install-2.1.0-beta.2 &&
cd ~/vps-secure-install-2.1.0-beta.2 &&
curl -fLO https://github.com/playfulsoul/vps-secure-script/releases/download/v2.1.0-beta.2/vps-secure-platform-2.1.0-beta.2.tar.gz &&
curl -fLO https://github.com/playfulsoul/vps-secure-script/releases/download/v2.1.0-beta.2/vps-secure-platform-2.1.0-beta.2.tar.gz.sha256 &&
sha256sum -c vps-secure-platform-2.1.0-beta.2.tar.gz.sha256 &&
tar --no-same-owner --no-same-permissions -xzf vps-secure-platform-2.1.0-beta.2.tar.gz &&
./install.sh &&
vps --version

已安装正式版的用户不会通过默认稳定通道收到 Beta。主动安装前确认自己接受预发布版本；完成后重新输入 vps，检查实际版本与更新通道。

1.x 老用户怎样迁移

旧菜单的“检查更新与自助升级”会按旧入口版本进入更新或迁移流程。1.x 与 2.x 不采用覆盖单文件的方式迁移；不要为了迁移先删除 SSH、UFW 或 Fail2Ban 配置。若旧入口仍停在 1.x，可按上面的完整包安装流程更换管理入口，安装后检查版本。

安装 2.x 只更换管理程序，不会自动重新初始化系统。已有 SSH 端口、业务应用和系统配置仍需在安装后分别检查。

03 首次安全与配置优化

首页 1 → 1「启动推荐配置向导」

适合希望一次完成基础防护和可选优化的用户。向导会配置 UFW 与 Fail2Ban，并让你选择常规软件更新、BBR 和 Swap。

  1. 先确认显示的 SSH 端口与当前登录端口相符。无法确认时，程序应停止。
  2. 按需求选择软件更新和 BBR；根据内存、磁盘及已有 Swap 决定是否新建 Swap。
  3. 阅读汇总计划，确认后才开始执行。
  4. 完成后保留原窗口，另开一个 SSH 窗口验证仍能登录；分别检查防火墙和防护状态。

正常结果：基础安全验证通过，并明确显示可选优化是否完成。已有 Swap 会保持现状；不默认开放网站端口 80/443。

失败处理：向导并不是一个“全部成功或全部撤销”的整体事务。例如 Fail2Ban 失败时，已配置的防火墙可能仍保留；BBR 或 Swap 失败也不会自动撤销已完成防护。按报错到对应单项检查或撤销，不反复运行整个向导。

该操作保留 SSH 端口，不自动关闭密码登录，也不自动禁止 root 登录。需要进一步强化时阅读 Beta 章节。

04 GitHub 公钥与 SSH 登录

首页 2 →「查看 SSH 端口」或「从 GitHub 导入登录公钥」

公钥放到 VPS，私钥留在你的客户端。GitHub 只提供公钥；从 GitHub 导入之后，Termius 仍需要选择与它配对的私钥。

第一次准备密钥

  1. 在自己的电脑检查是否已有 SSH 密钥。已有密钥不要覆盖。
  2. 没有时运行下面的生成命令，可为私钥设置保护口令。若提示文件已存在，取消覆盖。
  3. 把 id_ed25519.pub 的整行公钥加入 GitHub 的 SSH keys。不要上传不带 .pub 的私钥。
# 在自己的电脑执行
ssh-keygen -t ed25519 -C "my-computer"
cat ~/.ssh/id_ed25519.pub

Windows PowerShell 查看公钥可使用 Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub。

在 VPS 导入，再测试客户端

  1. 菜单选择“从 GitHub 导入登录公钥”，输入 GitHub 用户名，以及实际要登录的 VPS 用户。
  2. 核对显示的指纹后确认。多个 GitHub 公钥会分别处理；已有公钥不会重复追加。
  3. 在 Termius 的密钥管理中导入对应私钥，将它分配给该主机；主机用户名必须与刚才导入公钥的服务器用户一致，SSH 端口保持原值。
  4. 保留原连接，再打开新窗口测试。公钥导入成功不代表客户端已经选对私钥。

正常结果：新窗口可以使用密钥登录。私钥保护口令与服务器账户密码不同；是否真正采用公钥，以客户端认证日志或下面的独立测试为准。

在 Mac/Linux 验证只使用公钥（替换占位地址和端口）
ssh -o IdentitiesOnly=yes -o PreferredAuthentications=publickey \
  -o PasswordAuthentication=no -o KbdInteractiveAuthentication=no \
  -i ~/.ssh/id_ed25519 -p SSH端口 用户名@服务器地址

这条命令禁止退回服务器密码认证。它仍可能要求输入本机私钥保护口令。

失败处理：先核对用户名、端口和指纹。服务器可以用 ssh-keygen -lf ~/.ssh/authorized_keys 查看当前用户授权公钥指纹；本机用 ssh-keygen -lf ~/.ssh/id_ed25519.pub 对照。只分享脱敏错误，不分享私钥。

导入保留已有授权，并记录本次新增公钥。公钥撤销与程序版本恢复是不同操作；不要用删除整个 authorized_keys 的方式撤销一次导入。

05 防火墙与 SSH 防护

安装、检查 UFW

首页 2 →「检查防火墙运行与重启风险」→ 按结果选择「安装并启用防火墙」
  1. 检查 SSH 端口，以及是否有其他程序管理防火墙持久化规则。
  2. 确认后应用。程序保留现有规则，并为已确认的 SSH 端口补规则。
  3. 选择“查看防火墙状态”，再从外部打开新 SSH 连接，并测试原有网站或节点。

正常结果：UFW 配置、实际内核运行规则及开机恢复检查一致。仅显示 active 不能证明业务端口可达。

冲突处理：检查明确报告启动所有者冲突时，才使用“修复防火墙启动冲突”。升级程序不会自动执行这项系统修复。修复后重新验证业务连接。

业务端口放行

2.0.0 这组菜单没有任意业务端口的添加表单。部署应用前按应用实际监听协议放行；例如要允许 8443/TCP，可在 VPS 使用 sudo ufw allow 8443/tcp。端口数字是示例，请替换；UDP 仅在应用确实使用时另外放行。服务商安全组仍需单独核对。

不要为了排错直接清空 UFW。菜单“撤销上一次防火墙修改”只处理模块记录的改动；如果应用前 UFW 未启用，回滚可能恢复为关闭状态，之后应核对。

安装、检查 Fail2Ban

首页 2 →「安装并启用 SSH 防暴力破解」→「查看 SSH 防护状态」
  1. 确认当前 SSH 端口正确，再安装或应用。
  2. 查看服务与 sshd jail 是否通过验证，观察失败登录与封禁计数。
  3. 新开窗口测试正常登录。

模块写入自己的配置片段，保留 jail.local。没有 /var/log/auth.log 的系统可以使用 systemd 日志后端；“已安装”不等于服务运行。

误封自己：从服务商控制台登录，检查 sudo fail2ban-client status sshd。核实自己的当前出口 IP 后，用 sudo fail2ban-client set sshd unbanip 你的出口IP 定向解封；先修正密钥或密码错误再重试，避免再次触发封禁。

“撤销上一次 Fail2Ban 修改”可能恢复到此前未运行的状态。撤销后再次检查服务，不能把一次 socket 访问失败直接当作回滚失败。

06 系统优化与用户管理

更新系统软件

首页 3 → 1「系统软件更新」
  1. 查看有多少软件可更新；必要时先检查 APT。
  2. 选择“更新系统软件（不升级发行版）”，确认后等待结束。
  3. 阅读是否需要重启的提示，重新检查关键业务。

这与更新 vps 本身不同。遇到包管理锁，先等系统原有更新完成；不要删除锁文件强行继续。系统软件更新没有通用的一键还原保证。

Swap：磁盘上的应急内存

首页 3 → 2「Swap 虚拟内存」

Swap 可以缓解瞬时内存压力，但不能替代物理内存。已有 Swap 时先保持，不叠加创建。

  1. 选择“查看当前 Swap 状态”和兼容性检查。
  2. 需要创建时输入容量，例如 512M 或 1G；留意磁盘剩余空间。资源够用或业务不适合 Swap 时可以不设置。
  3. 确认创建后再次查看状态。

“撤销本工具创建的 Swap”只处理本模块管理的文件。撤销前应确认内存余量，不能把所有 Swap 都当作本工具创建。

BBR：拥塞控制算法

首页 3 → 3「BBR 网络加速」
  1. 检查系统支持情况，再查看当前状态。
  2. 内核支持且希望启用时，选择“启用 BBR 网络加速”。
  3. 再次查看当前拥塞控制是否为 bbr。

BBR 不保证所有线路都变快，也不增加服务商带宽上限。需要撤销时使用“恢复启用前的设置”；不支持时保持原配置。

普通用户与 sudo

首页 3 → 4「用户与 sudo 权限」
  1. 查看普通用户，避免重复创建。
  2. 选择“创建 sudo 用户”，按提示设置用户名与账户信息。
  3. 为该用户导入公钥，在新窗口登录并测试 sudo -v 和 sudo whoami；后者成功时显示 root。

创建普通用户不会自动关闭 root 登录。删除用户前确认不是当前会话或业务服务使用的账户；主目录是否删除要单独看操作提示，不把删用户作为登录排错手段。

07 应用安装与远程桌面

Docker 与 Compose

首页 4 → 1「Docker 容器引擎与 Compose」
  1. 先查看状态和系统支持情况。
  2. 选择安装 Docker Engine，检查计划中现有包冲突后确认。
  3. 安装后查看状态；用 docker --version 和 docker compose version 核对工具。

卸载入口保留容器数据，但会影响正在依赖引擎运行的容器。安装 Docker 并不等于已部署应用；容器端口发布及其防火墙行为需要按应用单独验证。

1Panel 管理面板

首页 4 → 2「1Panel 管理面板」
  1. 检查依赖，或先选择“下载并校验官方安装入口（不安装）”。
  2. 确认安装，按上游安装器的实际提示完成配置。
  3. 私下保存安装器显示的访问方式，在浏览器实际登录验证。

平台校验固定官方入口；后续流程仍由上游执行。不要把管理地址、账户或初始密码截图公开。卸载前先备份面板管理的应用与数据。

远程图形桌面

首页 4 → 3「远程图形桌面（SSH 安全通道）」
  1. 选择“检查配置并查看推荐”，再进入“引导安装”。
  2. 选择系统建议或 LXQt / XFCE / MATE 档位；指定普通桌面用户，再选择是否安装 Firefox、授予 sudo。
  3. 查看安装与服务状态，打开“查看远程连接方法”。
  4. 在自己电脑按输出建立 SSH 隧道，并保持隧道窗口打开；远程桌面客户端连接本地隧道端口。
  5. 用普通桌面用户登录，确认能看到桌面并操作。

LXQt 偏轻量、XFCE 均衡、MATE 更完整，实际以内存检查为准。RDP 只监听 VPS 回环地址，无需将 3389 暴露公网；root 图形登录被禁止。

中文字体缺失时选“补齐必要组件（中文字体）”。该操作不提供中文输入法。回滚或卸载保留普通用户与个人资料；图形会话清理不安全时会停止，按报错处理。

08 网络检查与第三方测试

立即检测与定时记录

首页 5「基础网络检查与监控」
  1. 选择“立即检测网络状态”，输入检测目标或采用默认值，确认发送 5 个 ICMP 请求。
  2. 查看结果中的延迟、丢包与网卡计数。
  3. 需要持续记录时，选择“配置并启动定时监控”，设置目标、采集间隔和保留天数；默认分别为 60 秒、30 天。
  4. 稍后查看最近结果并检查监控服务；不再需要时停止定时监控。

怎样读结果：至少两次采样才能计算两次之间的平均上下行速率；这不是主动带宽测速。VPS 到目标的延迟，也不是你家里到 VPS 的延迟。目标屏蔽 ICMP 时，丢包结果不能单独证明业务中断。

选一个符合问题的测试

首页 6「VPS 测试工具」
融合怪 / YABS综合性能、CPU、磁盘与网络检查。
Bench.sh查看测试节点方向的网络带宽。
NextTrace查看从 VPS 发出的路由探测结果。
流媒体 / IP 质量检查当时的服务可用性与 IP 评价。
  1. 先查看第三方工具来源，了解负载与流量提示。
  2. 选对应工具并确认，按工具自身提示完成。
  3. 保存所需的脱敏结果；结合时间、方向和业务体验判断。

这些工具以 root 运行，部分还会下载下游组件。入口校验不等于全部组件审计；综合或带宽测试可能消耗大量资源，不宜反复在承载业务的机器上运行。

09 更新、恢复与问题反馈

首页 8「诊断报告与程序维护」

检查并更新程序

  1. 选择“检查新版本”，核对当前版本、更新通道和说明。
  2. 选择“更新到最新版本”并确认；等待下载、SHA-256 校验、安装验证。
  3. 运行 vps --version 核对安装后的版本。

日常输入 vps 时会最多每天检查一次并提示，不会自行安装。正式版默认稳定通道，Beta 默认预发布通道。

旧版菜单进程可能仍显示旧版本。退出脚本并重新输入一次 vps 即可，无需退出 SSH。2.1.0-beta.1.1 修复了后续菜单更新/恢复后的自动切换；从更早版本首次升级到它的当次，仍需重新运行一次。

恢复上一程序版本

  1. 先选择“查看上一版本备份”。
  2. 确认确实需要恢复，再选择“恢复上一版本”。
  3. 核对版本并重新打开菜单。

恢复平台程序不会撤销 UFW、Fail2Ban、Swap 或 SSH 的系统修改。系统修改请用对应模块的撤销入口。提示操作中断或恢复失败时保留备份和事务记录，不删除锁强行继续。

体检和脱敏报告

首页 7 可运行服务器完整体检；发现问题时从首页 8 → 5 生成脱敏诊断报告。报告在 VPS 本地保存，程序显示路径，不自动上传。打开检查后再分享，并补充版本、操作名称、预期和实际结果。无需发送密码、私钥或完整配置。

只读检查命令
vps --version
vps doctor
vps firewall preflight
vps fail2ban status
vps update status

10 进阶登录安全：分阶段完成

首页 2 →「分阶段设置普通用户、密钥、密码和 root 策略」

正式版 2.0.0 只有登录基础与进阶说明。这个实际执行向导从 2.1.0-beta.1 提供；最新预发布为 2.1.0-beta.2，包含既有登录强化和菜单刷新修复。

  1. 保持当前管理员窗口，创建或复用普通 sudo 用户，导入该用户的 GitHub 公钥。
  2. 在新窗口用该普通用户和密钥登录，执行向导当次生成的完整验证命令，验证会话和 sudo。
  3. 首次验证通过后，才允许关闭 SSH 密码与键盘交互登录。
  4. 关闭后再开一个全新的密钥登录窗口，完成第二次验证。
  5. 第二次验证成功后，单独选择 root 仅允许公钥，或完全禁止 root 直接登录。

一次性验证令牌默认 30 分钟有效，只用于当次验证。不要直接照搬别人的令牌或省略新窗口步骤。禁用 root 前确认普通用户 sudo 和服务商控制台可用。

失败与恢复：准备或验证失败时不会解锁下一阶段；策略修改验证失败会尝试恢复原配置。sudo vps login rollback --yes 只恢复本模块上一次已提交登录策略，不删除新用户或已导入公钥。自动恢复失败时保留当前连接和报错证据。

12 常见故障：先判断发生在哪一步

现象先做什么
curl: command not found回到安装章节，安装 curl 与 HTTPS 证书后再下载。
sudo: unable to resolve host核对 hostname、/etc/hostname、/etc/hosts 的一致性；不要盲目替换整份 hosts。root 可暂时不加 sudo。
升级下载超时保留旧版本，核对 GitHub 网络可达性后重试；不跳过 SHA-256。旧客户端超时策略可能与新版不同。
升级后首页还是旧版本退出脚本，再输入 vps；参考 2.1.0-beta.1.1 首次启用说明。
公钥登录退回密码核对主机用户、客户端私钥、服务器公钥指纹；进行仅公钥测试，停止反复尝试错误凭据。
连接在 SSH 握手阶段关闭还不能归因于密钥。检查服务、封禁和服务器日志；失去 SSH 时使用服务商控制台。
自己的 IP 被封从控制台确认 sshd jail 中的当前出口 IP，定向解封后修正认证问题。
UFW active 但节点不可达检查运行与重启风险、实际监听、协议和服务商安全组；由诊断结果决定是否修复启动冲突。
Fail2Ban socket 不存在检查服务实际状态和日志。已安装不等于运行；回滚到此前 inactive 状态也可能出现。
VNC 中文菜单乱码可能是控制台字体不支持中文。优先用 SSH 阅读菜单；救援时用简短命令，不盲选乱码菜单。
提示事务中断 / 锁存在确认是否仍有安装任务运行，保留锁、备份和事务记录，按诊断结果恢复。
