# 测试指南

本项目会修改 SSH、防火墙、Fail2Ban 和系统服务。测试不仅要证明功能可以执行，也要证明失败时不会让用户失去访问或破坏已有配置。

## 测试层级

### 1. 静态检查

- 所有 Shell 文件通过 Bash 语法检查。
- 项目维护的 Shell 文件通过 ShellCheck。
- 文档链接、版本号和发行文件名保持一致。

### 2. 单元与契约测试

- 平台识别和 SSH 端口探测。
- 模块发现、操作白名单和路径边界。
- 防火墙、Fail2Ban、更新和迁移安全契约。
- 事务记录、幂等执行和回滚点保留。
- 普通菜单、纯文本模式和用户提示。

本地入口：

```bash
./tests/run.sh
```

### 3. 发行包测试

```bash
./scripts/build-release.sh
sha256sum -c dist/<发行包>.sha256
```

需要确认：

- 归档包含正确版本；
- 不包含开发临时文件或 macOS 扩展属性；
- 校验文件与归档一致；
- 从归档解压后的测试仍然通过。

### 4. 真实 VPS 集成测试

高风险模块必须在有控制台、快照或救援模式的专用测试机上验证。

执行原则：

- 保持当前 SSH 窗口；
- 修改 SSH 或防火墙后新开窗口验证；
- 记录修改前状态；
- 同时测试首次执行、重复执行、验证和回滚；
- 测试结束后恢复或记录最终状态；
- 第三方高流量工具不得在无人值守测试中执行。

## 必测安全场景

以 [`COMPATIBILITY.md`](../COMPATIBILITY.md) 的 Mandatory scenarios 为准，包括默认、自定义和多 SSH 端口、socket 激活、现有防火墙规则、journald/file 日志、重复执行、中断、锁竞争和验证失败。

## 测试记录

真实 VPS 验收需要在 `docs/` 中留下：

- 系统、内核和初始服务状态；
- 被测试的提交或发行版本；
- 操作和观察结果；
- 发现的问题及修复提交；
- 最终服务器状态；
- 尚未覆盖的场景。

## “通过”的含义

只有命令退出码成功并且目标状态经过独立检查，才能宣布通过。打印成功文字本身不构成验证证据。
